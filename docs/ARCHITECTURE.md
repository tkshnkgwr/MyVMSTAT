# システムアーキテクチャ設計書: MyVMSTAT

本ドキュメントは、**MyVMSTAT** の全体設計、採用技術スタック、ディレクトリ構造の意図、およびモジュール間のデータフローについて定義します。

---

## 1. システムの概要と目的

`MyVMSTAT` は、Linux 標準の `vmstat` コマンドにインスパイアされた、システムのリソース使用状況をリアルタイムで色付けして表示するコマンドラインユーティリティ（CLI）です。

### 目的
- **マルチプラットフォーム対応**: Linux環境のみならず、Windows 等の非Linux環境でも vmstat 風のリソース監視を行えるようにすること。
- **高視認性 (dstat 風)**: 数値の大きさや意味（アクティブ/非アクティブ/警告/限界値）に応じてANSIエスケープコードによるカラー強調を行い、一目で状態を把握可能にすること。
- **超軽量・省資源**: サーバーやローカル開発環境でバックグラウンド実行や常時監視に使用されることを想定し、最小限のバイナリサイズとメモリフットプリントで動作すること。

---

## 2. 採用している技術スタック

本プロジェクトは Rust 言語で実装されており、軽量かつ安全で信頼性の高い実行環境を実現しています。

| コンポーネント | 採用技術 | バージョン | 主な用途 / 役割 |
| :--- | :--- | :--- | :--- |
| **開発言語** | Rust | Edition 2021 | プログラム全体の記述、静的型安全性の保証 |
| **システム情報** | `sysinfo` | v0.39 | クロスプラットフォーム（特にWindows）でのシステムリソース取得 |
| **日時処理** | `chrono` | v0.4 | ローカルタイムスタンプの取得および文字列フォーマット処理 |
| **共通機能** | `common_lib` | 独自ライブラリ | Windows用デスクトップ機能（Named Mutex を利用した二重起動防止） |

## 3. アーキテクチャおよびディレクトリ構造の意図

### 3.1 ディレクトリ構造
リポジトリのレイアウトは以下のように整理されています。

```text
MyVMSTAT/
├── .agents/
│   └── AGENTS.md          # AIアシスタント向け開発・実行ガイドライン
├── .github/
│   └── workflows/         # GitHub Actions（CI/CD、自動リリース）
├── docs/
│   ├── ARCHITECTURE.md    # システムアーキテクチャ設計書（本書）
│   ├── DIAGRAM.md         # Mermaidによるシステム構成図・制御フロー
│   ├── FOOTPRINTS.md      # バイナリサイズやメモリ使用量の計測記録
│   ├── INSTRUCTIONS.md    # AI/開発者向けコーディングスタイル規約
│   ├── SPEC.md            # 詳細仕様書（パースロジック、閾値、引数）
│   ├── TEST_REPORT.md     # テストおよび検証結果の報告書
│   └── TODO.md            # 実装済み機能、直近タスク、バックログ管理
├── scripts/               # 開発用自動化・ビルド補助スクリプト
├── src/
│   └── main.rs            # アプリケーションのメインソースコード
├── Cargo.toml             # パッケージ・依存関係・リリースビルド定義
└── Cargo.lock             # 依存関係のバージョンロックファイル
```

### 3.2 構成の意図
- **単一ソースファイルによる高凝集性 (`src/main.rs`)**:
  プログラム全体の規模がコンパクト（1,000行未満）であるため、あえてモジュール分割によるオーバーヘッドを避け、単一の `main.rs` 内に集約してコンパイル速度とコードの見通しの良さを維持しています。
- **プラットフォーム抽象化**:
  Linux環境では、オーバーヘッドのない `/proc` ファイルシステムのパースを行い、非Linux環境（Windowsなど）では `sysinfo` クレートを利用するように条件付きコンパイル（`#[cfg(...)]`）で切り分けています。
- **ドキュメントの独立管理**:
  ソースコード、システム仕様、検証結果、リソース記録などを明確に分離し、すべて大文字スネークケースで命名された Markdown ファイルとして `docs/` ディレクトリに整理することで、ポータビリティと可読性を高めています。

## 4. データフローと主要モジュール間の連携

アプリケーションは単一のスレッド上で動作し、初期化、引数パース、および定期的なサンプリングループを行います。

### 4.1 プロバイダ抽象化とファクトリパターン
システムデータの取得は `TelemetryProvider` トレイトによって抽象化されており、プラットフォームに応じた構造体が生成されます。

```text
                      +-----------------------------+
                      |      TelemetryProvider      | <--- トレイト定義
                      +--------------+--------------+
                                     |
              +----------------------+----------------------+
              | (Linux環境)                                 | (非Linux/Windows環境)
              v                                             v
  +-----------------------+                     +-----------------------+
  |     LinuxProvider     |                     |    SysinfoProvider    |
  |  - /proc/stat         |                     |  - sysinfo::System    |
  |  - /proc/meminfo      |                     +-----------------------+
  +-----------------------+
```

1. **ファクトリ関数 `get_provider()`**:
   - `#[cfg(target_os = "linux")]` 時は `LinuxProvider` をボックス化して返します。
   - `#[cfg(not(target_os = "linux"))]` 時は `SysinfoProvider` をボックス化して返します。

### 4.2 主要データフローとサンプリング処理
メインループでは、指定された `delay` 秒間隔で以下の順序でデータが流れます。

```text
 [開始]
   │
   ▼
[二重起動チェック] ── (Windowsの場合、Named Mutex を用いて競合があれば即終了)
   │
   ▼
[引数解析 (parse_args)] ── (delay, count の決定)
   │
   ▼
[初回データ取得] ── (プロバイダ初期化とチック値のウォームアップ)
   │
   ▼
[ヘッダー表示]
   │
   ├──◄────────────────────────────────────────────────────+
   ▼                                                       │
[ループ開始]                                               │
   │                                                       │
   ├──► [TelemetryProvider::get_delta()]                   │
   │    前回取得データとの差分を計算（秒間レートへ変換）   │
   │                                                       │
   ├──► [print_row()]                                      │
   │    数値を ANSI カラーコードで修飾して標準出力へ一行表示│
   │                                                       │
   ├──► [終了判定]                                         │
   │    指定された `count` に達した場合はループを抜けて終了  │
   │                                                       │
   ▼                                                       │
[thread::sleep(delay)] ────────────────────────────────────+
   │
   ▼
 [終了]
```

- **差分レート計算の重要性**:
  コンテキストスイッチ数（`cs`）、割り込み数（`in`）、およびCPU使用率はシステム側で「起動からの累積値」として保持されているため、正確な現在値を出すために「前回のデータと今回のデータの差分」を計算し、`delay` 秒で除算した値を算出します。
