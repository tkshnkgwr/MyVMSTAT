# コントリビューション規約: CONTRIBUTING

本プロジェクトへの開発参加・貢献（プルリクエストの提出、Issueの報告など）を行う際のガイドラインです。

---

## 1. 開発環境の構築

開発を始める前に、Rust ツールチェーンがインストールされていることを確認してください。

- **Rust エディション**: `Edition 2021` 以降
- **推奨端末**: Windows 11 (PowerShell 7) または Linux / macOS
- **依存ライブラリのクローン**:
  本プロジェクトは同一オーナーの `common_lib` 共有ライブラリ（`../common_lib`）に依存しています。ローカル環境でビルドする際は、親ディレクトリの同一階層に `common_lib` をクローンして配置してください。

```text
workspace/
├── common_lib/  (https://github.com/tkshnkgwr/common_lib)
└── MyVMSTAT/    (本リポジトリ)
```

---

## 2. コミットメッセージ規約

コミットメッセージは、履歴の追跡性を高めるため、以下の **Conventional Commits** 形式に準拠してください。

```text
<type>: <記述>
```

### 指定する `<type>` の種類:
- `feat:` 新機能追加
- `fix:` バグ修正
- `docs:` ドキュメントの追加・変更（コード変更なし）
- `refactor:` リファクタリング（機能変更を伴わないコード構造の整理）
- `perf:` パフォーマンス最適化
- `test:` 自動テストの追加や修正
- `chore:` ビルドプロファイル、依存ライブラリ、CI/CDの設定更新など

---

## 3. プルリクエスト（PR）の提出手順

1. **ブランチ作成**:
   `main` ブランチから機能ごとのトピックブランチ（例：`feature/add-json-format`）を作成します。
2. **実装とローカル検証**:
   コードを修正した後、`TESTING.md` に記載されている「2. ローカルでの自動検証（`cargo test`、`cargo clippy` 等）」を実行し、すべて合格することを確認します。
3. **コミット & プッシュ**:
   Conventional Commits 規約に従ったコミットメッセージを作成し、プッシュします。
4. **ドキュメントの更新**:
   ソースコードの変更を伴う場合は、`.agents/AGENTS.md` の「自動ドキュメンテーションルール」に則り、`CHANGELOG.md` を含む関連ドキュメントを更新して同一コミット（またはPR内）に含めてください。
