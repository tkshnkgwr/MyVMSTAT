# テスト・検証方針: TESTING

本ドキュメントは、**MyVMSTAT** プロジェクトにおけるテスト方針、検証項目、および開発者がコミット前またはリリース前に実行すべきローカル検証手順について定義します。

---

## 1. テストの方針

本ツールは極めて高い動作の信頼性と、省リソース性を保証するため、以下の3つの観点から検証を行います。
1. **自動単体テスト (Unit Testing)**: 主要ロジック、パース処理、およびヘルプメッセージ判定などの静的ロジック。
2. **静的解析・品質検査 (Static Analysis)**: Rust のコンパイラ警告および `clippy` によるコード品質の最大化。
3. **手動検証 (Manual Verification)**: 実際のターミナルでの ANSI カラー表示と引数エラーハンドリングの動作確認。

---

## 2. ローカルでの自動検証コマンド

ソースコードに変更を加えた際、またはコミット・プッシュする前には、ローカル環境で以下のコマンドを順次実行し、すべての検査が「エラー・警告ゼロ」で合格することを確認してください。

### 2.1 自動テストの実行
すべての単体テストケースを実行します。
```bash
cargo test
```

### 2.2 コード品質チェック (Clippy)
プロジェクトに適用されている警告をエラーとして扱い、厳格にコード検査を行います。
```bash
cargo clippy --all-targets -- -D warnings
```

### 2.3 コードフォーマットチェック
コード全体のインデントやスタイルが Rust の標準書式に準拠しているか確認します。
```bash
cargo fmt --check
```
※もしフォーマット違反が検知された場合は、`cargo fmt` を実行して自動整形してください。

### 2.4 Rustdoc 生成テスト
Rustdoc ドキュメントコメントに構文エラーや警告がないかテストします。
```bash
cargo doc --no-deps --document-private-items
```

---

## 3. 手動検証の確認項目

OS に依存する挙動や、CLI のインターフェース動作については手動で以下の項目を確認します。

### 3.1 正常系の動作確認
- 指定した間隔（ delay ）でテーブルが更新され、値が出力されること。
- CPU やメモリ使用率に応じて、ANSI カラーコードが適切に適用され着色されていること（ゼロ値が灰色、高負荷が黄色・赤色太字等）。
- `count` を指定した際に、指定回数出力された後にプロセスが正常終了（終了コード `0` ）すること。

### 3.2 異常系・バリデーションの動作確認
- 不正な引数を指定した場合に、「Invalid option」や「Too many arguments.」などのエラーメッセージが表示され、終了コード `1` で終了すること。
- **Windows Named Mutex の検証**:
  Windows 環境でアプリケーションを実行中に、別のターミナルから再度起動を試みた際、二重起動がブロックされて「Error: Another instance of MyVMSTAT is already running.」が出力されること。
