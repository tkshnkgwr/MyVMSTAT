# リリリース手順書: RELEASE

本ドキュメントは、**MyVMSTAT** のバージョンアップおよびリリース作業の手順について定義します。

---

## 1. 自動リリースフローの概要

本プロジェクトでは、GitHub Actions による継続的インテグレーション（CI/CD）とリリース自動化（MiSysMonと同等設計）が導入されています。

- **バージョン自動繰り上げ**:
  `main` ブランチへコミットがプッシュまたはマージされた際、自動バージョンアップワークフロー（`.github/workflows/bump-version.yml`）が実行され、自動的にパッチバージョンをバンプ（例：`1.3.0` $\rightarrow$ `1.3.1`）します。
- **自動タグ生成・ビルド**:
  バンプされたバージョン情報を元に、Git タグが自動で打たれ、リリースビルドワークフロー（`.github/workflows/release.yml`）によって自動でコンパイル・パッケージングされ、GitHub Releases にドラフトまたは本公開のアセットが配置されます。

---

## 2. バージョン更新スクリプトの仕組み

バージョンアップ時には、手動によるファイルの書き換え漏れを防ぐため、PowerShell スクリプト `scripts/bump-version.ps1` が内部で呼び出されます。

このスクリプトは、以下のファイルをスキャンし、バージョン文字列を自動的に最新に同期させます。
1. **`Cargo.toml`** の `version` フィールド
2. **`docs/ja/SPEC.md`** および **`docs/en/SPEC.md`** 内のバージョン関連表記

---

## 3. 手動でのリリースタグ作成 (必要時)

もし自動リリースワークフローをバイパスし、手動で特定のメジャー/マイナーバージョン（例：`1.4.0`）をリリースしたい場合は、以下の手順に従ってください。

1. **ローカル検証**:
   `TESTING.md` に記載されている「2. ローカルでの自動検証」を実行し、警告やテスト失敗がないことを確認します。
2. **バージョン手動書き換え**:
   `Cargo.toml` の `version` フィールドを手動で更新し、コミットします。
3. **タグのプッシュ**:
   ```bash
   git tag v1.4.0
   git push origin v1.4.0
   ```
4. **GitHub Releases での確認**:
   タグのプッシュを検知して `.github/workflows/release.yml` が動き、Windows/Linux 向けのビルドバイナリ（`.zip` / `.tar.gz`）が自動ビルドされ、リリースアセットとしてアップロードされます。
